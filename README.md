# nmMRI SN Manual-Segmentation Framework

A minimal, reproducible workflow for **multi-rater manual segmentation of the
substantia nigra (SN)** on neuromelanin-sensitive MRI (NM-MRI), using ITK-SNAP,
with the **cerebral peduncle (CP)** segmented as a reference region.

It generates a phase-based, per-rater workspace from configurable subject lists,
then computes Dice, inter-rater agreement, and CP protocol checks. Everything is config-driven, no paths are hard-coded, and runnable from scripts.

## Structure

```
config/      paths, raters, phase definitions, subject lists (edit these)
scripts/     split_subjects, make_workspace, QC (qc_metrics, interrater_analysis,
             run_qc + qc_analysis/qc_visualize/qc_report, qc_protocol), utils
docs/        workflow, segmentation protocol, per-phase guides, ITK-SNAP guide,
             QC, label definitions (SN = 1, CP = 2)
environment.yml
```

## Quickstart

```bash
conda env create -f environment.yml
conda activate nmmri-manseg

# Edit config/paths.yaml (data + workspace locations), raters.json, phases.yaml,
# and the subject lists. Then:
python scripts/split_subjects.py --dry-run        # preview the split
python scripts/split_subjects.py                  # write it (append-only; seed in phases.yaml)
python scripts/make_workspace.py --dry-run        # preview the tree
python scripts/make_workspace.py                  # build it (copies inputs)

# Raters segment in ITK-SNAP, then:
python scripts/qc_metrics.py --phase phase4
python scripts/interrater_analysis.py --phase phase4
python scripts/qc_protocol.py --phase phase4      # CP rules + reference intensity
```

## Phases

| Phase | Name             | Expert mask | Labels  | Output              | Subjects    |
|-------|------------------|-------------|---------|---------------------|-------------|
| 1     | Playground       | yes         | SN      | `<INIT>_mask_a1/a2` | shared      |
| 2     | Practice         | yes         | SN      | `<INIT>_mask_a1/a2` | shared      |
| 3     | Mock exam        | no          | SN + CP | `<INIT>_mask`       | shared      |
| 4     | Exam             | no          | SN + CP | `<INIT>_mask`       | shared      |
| 5     | SNIT calibration | no          | SN + CP | `<INIT>_mask`       | shared      |
| 6     | Production       | no          | SN + CP | `<INIT>_mask`       | partitioned |

Phases 1–4 use the labeled set (Echo 1 images); Phases 5–6 use the SNIT NM
combined-echo ("combo echo") images, run 1 by default. See
[docs/overview.md](docs/overview.md) for the full workflow and workspace layout,
[docs/segmentation_protocol.md](docs/segmentation_protocol.md) for what is
segmented, and [docs/qc.md](docs/qc.md) for QC details.

## Notes

- Raw MRI data and rater outputs are never committed (see
  [.gitignore](.gitignore)). The repo holds code, config, and docs only.
- Workspace scans are relabeled to anonymized IDs (e.g. `sub-0001`) for
  blinding; the workspace → source key (`config/subjects_split.json`) is
  generated by `split_subjects.py` and git-ignored. keep it private.
- Source datasets may be BIDS-style or flat (`layout` per pool in
  [config/paths.yaml](config/paths.yaml)), with `.nii` or `.nii.gz` files, and
  a pool may span several dataset roots (the SNIT adults and adolescents);
  workspace inputs are normalized to gzip `.nii.gz`. The SNIT run is set once
  with `run` in paths.yaml.
- The split is append-only: once `config/subjects_split.json` exists,
  re-running `split_subjects.py` allocates only phases new to phases.yaml and
  never moves an existing subject or ID (`--regenerate` rebuilds everything
  from the seed). The previous key is backed up next to it before every write.
- Raters R1, R2 and R3 started first; R4, R5, R6, R7 and R8 joined later and
  start at Phase 1. Raters added to raters.json get every shared phase;
  production is re-divided with `split_subjects.py --repartition phase6
  --workspace <ws>`, which keeps a subject with any rater who already has output
  files for it, or is left for a later division with `--defer phase6`.
- Production (Phase 6) gives about 10% of its subjects to every rater (the
  overlap, always including sub-1093 and sub-5064) and divides the rest at
  random across raters.
- The five SNIT calibration scans are a fixed list in phases.yaml. They also
  keep their production assignment, under other workspace IDs.
- `make_workspace.py` never overwrites an input already in place (`--overwrite`
  forces it) and never removes folders; `--workspace`, `--phase` and `--raters`
  limit where and what it builds.
