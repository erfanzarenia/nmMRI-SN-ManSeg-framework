# nmMRI SN Manual-Segmentation Framework

A minimal, reproducible workflow for **multi-rater manual segmentation of the
substantia nigra (SN)** on neuromelanin-sensitive MRI (NM-MRI), using ITK-SNAP,
with the **cerebral peduncle (CP)** segmented as a reference region.

It generates a phase-based, per-rater workspace from configurable subject lists,
then computes Dice, inter-rater agreement, and CP protocol checks. Everything is config-driven, no paths are hard-coded, and runnable from scripts.

## Structure

```
config/      example paths, raters, phase definitions, subject lists;
             your own go in config/local/ (git-ignored)
scripts/     split_subjects, make_workspace, phase_manifest, QC (run_qc +
             qc_analysis/qc_visualize/qc_report, qc_protocol), utils
docs/        workflow, segmentation protocol, per-phase guides, ITK-SNAP guide,
             QC, label definitions (SN = 1, CP = 2)
environment.yml
```

## Quickstart

```bash
conda env create -f environment.yml
conda activate nmmri-manseg

# Copy config/* to config/local/ and edit paths.yaml (data + workspace
# locations), raters.json, phases.yaml and the subject lists. Then:
python scripts/split_subjects.py --dry-run        # preview the split
python scripts/split_subjects.py                  # write it (append-only; seed in phases.yaml)
python scripts/make_workspace.py --dry-run        # preview the tree
python scripts/make_workspace.py                  # build it (copies inputs)

# Raters segment in ITK-SNAP, then run QC (metrics, figures, reports, coverage):
python scripts/run_qc.py phase4
```

Masks saved before hole filling (`_unfilled` at the end of the name, every phase)
get a QC of their own in `qc/unfilled/`, laid out like `qc/`, with the same workflow and
criteria; the usual QC never uses them. See [docs/qc.md](docs/qc.md).

## Phases

| Phase | Name             | Expert mask | Labels  | Output              | Subjects    |
|-------|------------------|-------------|---------|---------------------|-------------|
| 1     | Playground       | yes         | SN      | `<INIT>_mask_a1/a2` | shared      |
| 2     | Practice         | yes         | SN      | `<INIT>_mask_a1/a2` | shared      |
| 3     | Mock exam        | no          | SN + CP | `<INIT>_mask`       | shared      |
| 4     | Exam             | no          | SN + CP | `<INIT>_mask`       | shared      |
| 5     | Calibration      | no          | SN + CP | `<INIT>_mask`       | shared      |
| 6     | Production       | no          | SN + CP | `<INIT>_mask_run_N_combo`, `_echo` | partitioned |

In the example configuration, Phases 1–4 use the labeled set (Echo 1 images)
and Phases 5–6 the study set's NM combined-echo ("combo") images: run 1 in
Phase 5, and every run in Phase 6, each also as its Echo 1 image, with one run
per subject enough. See
[docs/overview.md](docs/overview.md) for the full workflow and workspace layout,
[docs/segmentation_protocol.md](docs/segmentation_protocol.md) for what is
segmented, and [docs/qc.md](docs/qc.md) for QC details.

## Notes

- Raw MRI data and rater outputs are never committed (see
  [.gitignore](.gitignore)). The repo holds code, example config, and docs only.
- Keep your own config in `config/local/` (git-ignored): copy the files of
  `config/` there and edit them. The scripts read `config/local/` whenever it has
  a `paths.yaml`, else `config/` (`MANSEG_CONFIG_DIR` or `--config-dir` point
  elsewhere). Everything the scripts write next to the config (the split key, the
  manifests) lands there too. Your own versions of the rater guides go in
  `config/local/docs/`: `make_workspace.py` copies them into the workspace
  instead of the ones in `docs/`. See [config/README.md](config/README.md).
- Workspace scans are relabeled to anonymized IDs (e.g. `sub-0001`) for
  blinding; the workspace → source key (`subjects_split.json`) is generated by
  `split_subjects.py` and stays private.
- Source datasets may be BIDS-style or flat (`layout` per pool in paths.yaml),
  with `.nii` or `.nii.gz` files, and a pool may span several dataset roots;
  workspace inputs are normalized to gzip `.nii.gz`. The run of a single-image
  phase is `run` in paths.yaml; a phase with `runs` in phases.yaml gets each of
  those runs.
- The split is append-only: once `subjects_split.json` exists, re-running
  `split_subjects.py` allocates only phases new to phases.yaml and never moves an
  existing subject or ID (`--regenerate` rebuilds everything from the seed). The
  previous key is backed up next to it before every write.
- Raters added to raters.json get every shared phase; a partitioned phase is
  re-divided with `split_subjects.py --repartition phaseN --workspace <ws>`, which
  keeps a subject with any rater who already has output files for it, or is left
  for a later division with `--defer phaseN`. `raters` in a phase limits it to
  those raters.
- Production (Phase 6) gives `overlap` subjects to every rater (always including
  `overlap_subjects`, split evenly across `balance_by`, e.g. age group) and
  divides the rest at random, evenly per rater and per group. Its subjects follow
  the study list (participant, age group, notes); `--repartition` gives newly
  listed subjects new IDs, keeps existing ones, and drops unlisted ones that have
  no outputs. `--add-new phaseN` adds new subjects only, each to the rater with
  the fewest, and moves nothing else.
- With `runs: [1, 2]` each acquisition is its own image, and `echoes: [combo,
  echo]` offers each run as two images, `inputs/<sub>/image_run_<N>_combo.nii.gz`
  (the pool's image_pattern) and `image_run_<N>_echo.nii.gz` (Echo 1, the pool's
  `echo_patterns`); the rater segments one of them per run, as
  `outputs/<sub>/<INIT>_mask_run_<N>_combo.nii.gz` or `_echo.nii.gz`.
  `runs_required: 1` makes any one run enough for a subject (without it every run
  is needed). QC compares masks only on the same run and image, and its run check
  fails an overlap subject where a rater shares no run and image with any other
  rater. `run1_only` keeps listed subjects to run 1. A file naming no run or no
  image is flagged and not used.
- To even out a phase in progress use `split_subjects.py --rebalance phaseN
  --hold-next 5 --hold <RATER>:<ID>`: it keeps the overlap and every assignment
  apart from the few subjects handed over, then `make_workspace.py --phase phaseN
  --archive-unassigned` moves those folders to `<ws>/archive/` (never one holding
  an output file), and `phase_manifest.py phaseN` writes the private manifests
  (assignments, acquisitions) and checks the workspace against them.
- `make_workspace.py` never overwrites an input already in place (`--overwrite`
  forces it) and never removes folders; `--workspace`, `--phase` and `--raters`
  limit where and what it builds.
